# GOAP CORE

This folder contains a lightweight Goal Oriented Action Planning implementation used by Heroes. The system is built around immutable-style state transitions and a planner that searches for a sequence of actions to satisfy the most important unmet goal.

The world model is split between `AgentState` and a read-only world snapshot. `AgentState` is a value type that stores beliefs as a float array indexed by integer IDs. It supports cloning, value equality, and hashing so states can be compared and cached. `AgentContext<TSnapshot>` wraps an `AgentState` and a `IReadOnlyWorldSnapshot`, cloning the state on construction while keeping the snapshot reference. `AgentStateExtensions` provide utilities to evolve states in a functional way. `Mutate` applies a ref mutator and returns a new state, while `Clamp` and `Bucket` normalize belief values to a range or a discrete step.

Goals are described by `Goal<TSnapshot>`. A goal has a priority, a name/description, and three delegates: `Importance` for dynamic scoring, `Achieved` to verify completion, and `Heuristic` to estimate remaining cost. The planner uses `Importance * Priority` to rank candidate goals and will skip any goals already achieved in the current context. Actions are described by `Action<TAgent, TSnapshot>`, which binds a name/description with `PreConditions`, `Effect`, `Time`, and an `Implementation` delegate. The `Effect` delegate is expected to be pure and return the next `AgentState` (never mutate `ctx.state` in place), while `Implementation` returns an `IActionStrategy` that performs gameplay side effects when a plan is executed.

`Planner<TAgent, TSnapshot>` performs an iterative deepening A* search over actions with a cost cutoff derived from the goal heuristic. It keeps a stack of states, costs, and chosen actions, and returns the first plan that reaches the goal within the depth and cost limits. A `TranspositionTable` caches the best known cost for a state and prevents revisiting states when the new path is not cheaper. This helps control the branching factor without enforcing strict action ordering.

`Archetype<TAgent, TSnapshot>` is a thin container that holds a set of actions, goals, and a base state. It allows each agent archetype to reuse the same planner with a tailored list of available actions and objectives.

World state is accessed through `IWorldState<TSnapshot>` and `IReadOnlyWorldSnapshot`. The planner always uses a snapshot created at planning time, so heuristics and preconditions read a consistent world view. If you need an implementation, derive from `WorldStateBase<TSnapshot>` in your game layer and supply a snapshot type with `Version` and `IsValid`.

Typical flow is to build actions and goals with their builders, construct an `Archetype<TAgent, TSnapshot>`, and then call `Planner<TAgent, TSnapshot>.Plan` with the current `AgentContext<TSnapshot>`. The returned `Plan<TAgent, TSnapshot>` contains a stack of steps that can be executed via `PlanExecutor<TAgent, TSnapshot>` or by repeatedly calling `StartNextStep` and `Update` while applying each action’s `Implementation` for gameplay and `Effect` for predicted state transitions during planning.
